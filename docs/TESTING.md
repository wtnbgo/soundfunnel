# 動作確認の方法

## 1 台で複数起動して試す

`--profile NAME` を付けると設定ファイルが分かれ、1 台で何個でも起動できます。
プロファイル付きでは音声ポートも空きポートを使います。

**同じ PC で試すときは、マイクとスピーカーのループに注意してください。**
複数のインスタンスが同じマイクを拾い、サーバがスピーカーで鳴らすとハウリングします。

- サーバ役: `--silent --test-tone`（出力を開かない。入力はオーディオのクロック代わりにだけ使う）
- クライアント役: `--silent --test-tone`（マイクの代わりに 440 Hz のテスト音を送る）
- システムの音を送るクライアント（`--loopback`）を試すときも、サーバ役は必ず `--silent` にする。
  サーバが鳴らした音をループバックがまた拾い、無限に回り続けるため。

例（Windows、PowerShell）:

```powershell
.\SoundFunnel.exe --profile A --background --silent --test-tone --status-file A.json --control-file A.cmd
```

```powershell
.\SoundFunnel.exe --profile B --background --silent --test-tone --status-file B.json --control-file B.cmd
```

各プロファイルの設定ファイルに同じ `groupKey` を書いておくか、画面の「グループ」タブで設定します。

## 状態ファイルとコマンドファイル

`--status-file F` を付けると、1 秒ごとに状態を JSON で書き出します。

| キー | 内容 |
|---|---|
| `status` / `role` / `server` | 画面に出る状態、役割（0 グループ未設定 / 1 サーバ未設定 / 2 サーバがオフライン / 3 クライアント / 4 サーバ）、サーバ名 |
| `discovery` | 検出の統計: `raw` 受信数、`ok` 認証できた数、`bad` 認証失敗、`sent` / `senderr` 送信数と失敗数、`if` インターフェース数 |
| `net` | 音声の統計: `rx` 受信、`routed` 受け付けた数、`dropped` 破棄、`tx` 送信、`cb` オーディオのコールバック回数 |
| `device` | 開いているオーディオデバイス |
| `loopback` | システムの音を送っているときの取り込み元（または エラー） |
| `sendLevel` | クライアントの送信レベル |
| `members` | 見えている PC の一覧（`receiving` と `level` はサーバが受信している音） |

`--control-file F` を付けると、F に書かれたコマンドを 1 つ読んで実行し、F を消します。

| コマンド | 動作 |
|---|---|
| `server` | このPCをサーバにする |
| `pause` / `resume` | 送信の一時停止 / 再開 |
| `mute <名前>` / `unmute <名前>` | （サーバで）その PC をミュート / 解除 |

`--log-file F` を付けると、起動・検出・デバイス・送信エラーなどをログに書きます。

## 複数台での確認項目

1. 全台が互いに見える（`members` に全台が出る。`discovery` の `ok` が増える）。
2. サーバで、各クライアントが `receiving: true`、`level` が 0.1 前後（テスト音の場合）。
3. サーバから `mute` すると、そのクライアントの `net` の `tx` が止まる。`unmute` で再開する。
4. 別の PC で `server` を実行すると、ほかの全台の音がその PC に届く。
5. サーバを止めると、クライアントは「サーバがオフラインです」になる。サーバを起動し直すと自動で戻る。

macOS では、初回（とビルドし直すたび）にマイクとローカルネットワークの許可が必要です。
許可されるまでオーディオデバイスを開かず（`cb` が 0）、マルチキャスト送信も失敗します（`senderr` が増える）。
